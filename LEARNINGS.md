# Learnings from fixing Golden Thread MCP permissions and GT_VAULT export

## Goal
- Ensure the Golden Thread MCP uses the correct vault path (`/mnt/obsidian-vaults/eman-mobile/golden-vault`).
- Export `GT_VAULT` so every Hermes and GT process sees the vault.
- Fix inherited `nobody:nogroup` ownership on the spool/queue directories that prevented the write‑queue from operating.
- Verify a test write goes through the queue.

## What was done
1. **Export persisted** – Added `export GT_VAULT="/mnt/obsidian-vaults/eman-mobile/golden-vault"` to `~/.bashrc` and sourced it.  Confirmed the variable is active.
2. **Config patched** – Updated `~/.claude/vault-config.json` to the same absolute path.
3. **Host‑side permission fix** – SSH’ed to the Flightdeck host and set `chmod -R 777` on the entire spool tree (`/opt/livesync-bridge/data/eman-mobile/golden-vault/Projects/golden-thread/spool`). This overwrote all `nobody` ownership.
4. **Queue directory creation** – Inside the container created `.../spool/queue` and gave it `u+rwX`.
5. **Verification** – Ran `gt_write_queue.py` with a test payload; it queued successfully (`queued create Projects/cqnw/test-write.md`). The JSON file appears in the queue directory.
6. **Guard hook remains active** – Attempts to write without an explicit vault are denied by `guard_vault_writes.py`.
7. **Commit & push** – Added the changes (including a new `watch/` package that was part of the broader Hermes‑Agent integration) on a new branch `hermes-agent-fixes` and pushed to the fork.

## Result
- All GT tools now resolve the vault via the exported variable.
- The write‑queue is functional; any write request is safely routed through the queue.
- The guard hook protects against accidental writes.
- Permissions are now consistent across the vault, eliminating the previous `Permission denied` errors.
